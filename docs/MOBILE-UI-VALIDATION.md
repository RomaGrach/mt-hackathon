# Экранный интерфейс и проверка — 27.09.2026

## Основание

Повторно прочитаны постановки основной цепочки #19–#26 и обсуждения #21, #24, #26. Решение #21: Incident описывает ситуацию, Task — рабочее дело; источник promise не создаёт отдельную сущность Commitment. В предыдущей поставке UI ошибочно фильтровал Task только по type=promise. Это исправлено: отображаются все разрешённые серверной проекцией задачи, включая этап приёмки, инциденты, адресный возврат, выполненные и просроченные задачи. Необнаруженное обстоятельство не раскрывается заранее.

Последние требования владельца имеют приоритет над старым дизайном #24: одна верхняя панель, экранная структура, главная с профилем, нижняя навигация, полная игра вместо сокращённого прототипа. Открытый тестовый администратор сохранён.

## Реализация

- Один общий HUD: РЕЙС 400, часы, две компактные полосы, меню и срочный таймер при необходимости.
- Текст ситуации вверху; все предлагаемые сервером варианты сохранены. В стандартном мобильном размере кнопки снизу; на маленьком экране прокручивается текстовая область, а не вся страница. Низкие окна и увеличение текста сохраняют возможность прокрутки, без обрезания управления.
- Нижние панели «Вагон», «Задачи», «Обучение», «Ещё» открываются локально через native dialog с закрытием, фокусом и Escape. Карта — условная схема зон, не выдуманная планировка класса.
- Главная: учебный профиль, начало/продолжение, параметры смены, обучение, цель и полный каталог. Профиль: навыки, история, достижения, цель и настройки отдельными панелями. Рейтинг бригады/депо/компании и уведомления доступны снизу.
- Сохранены две формы v2, четыре класса, обучение/проверка/три политики таймера, переходы, все действия и исходы, replay, XP, пять v1-сценариев со всеми концовками. Изменение не добавляет несуществующие сценарии сверх авторского каталога.

## Быстродействие

До изменения Worker logs показывали обычные API 184–687 мс и отдельные первые bootstrap 1886–3137 мс. Это наблюдения, не лабораторный benchmark.

Убран обязательный GET после каждого успешного POST: используется полный авторитетный ответ команды. При восстановлении потерянного ответа и внутреннем retry GET сохранён. Убраны повторные bootstrap при локальной навигации и запуске. Панели не запрашивают API.

Worker не сжимает/записывает SQLite snapshot, если total_changes=0; записи и timeout по-прежнему проходят CAS. Backfill исторических v1-наград фиксируется один раз в runtime_metadata, вместо сканирования всех профилей при каждом клике. Завершения v1 продолжают сохранять награды штатно. Браузерный JS собран в один entry, без цепочки загрузки модулей. Static no-cache предотвращает смешивание старых и новых модулей после публикации.

## Проверено

- 99 Node unit/integration tests: все пройдены. В том числе полный маршрут, четыре исхода/timeout, классы и формы, replay, storage, публичная сводка, все Task/Action в HTML, один POST для нового действия, GET после retry и отсутствие записи при read-only запросе.
- Syntax/OpenAPI, оба content validators, Prettier и Sites build — пройдены.
- Реальный Chrome через supervised Vite preview с тем же Node backend, без локальной подмены игрового движка. QA-страница `qa/mobile.html` предоставляет iframe 390×844 и 320×740, счётчик фактических API resource entries. Не входит в production bundle.
- Вручную в браузере пройдена вся смена: приёмка → обращение → осмотр → освобождение прохода → передача → ожидание подтверждения → возврат к месту 18 → завершение → причинный разбор → подтверждение. Результат 70/70, лояльность 85, безопасность 90, XP 20.
- Проверены две ситуации на карте, все известные/завершённые задачи, обучение, профиль и три области рейтинга, уведомления.
- На 390×844 все три длинных выбора сцены прохода располагались до y=745, над нижней панелью. На 320×740 после исправления высота документа 740, ширина 305 при viewport 320, обе кнопки приёмки до y=641. Горизонтальной прокрутки нет.
- Проверено: после bootstrap + создания смены + begin — 3 API-запроса. Открытие/закрытие задач и обучения и последующее ожидание не увеличили счётчик. Возврат фокуса по-прежнему обновляет состояние.

## Границы доказательств

Эмуляция размеров в реальном браузере, не физический слабый телефон и не тест 3–5 проводниками. Worker/D1 проверены адаптерными тестами и успешной сборкой; браузерный проход использовал Node backend. Нет заявления о конкретном ускорении production в процентах. GitHub Actions ранее не стартовал из-за ограничений аккаунта; успешный удалённый CI не заявляется.

## Исправление администратора и меню — 27 сентября 2026

- Администратор теперь всегда имеет отдельный плоский экран, независимо от наличия игровой сессии. Убраны вложенная игровая оболочка и широкая прокручиваемая таблица.
- Игроки показаны строками с бригадой и цветовым статусом. Раскрытие строки показывает все прежние показатели: попытки, завершения, XP, лояльность, безопасность, активность и просроченную задачу. Пагинация и публичный доступ сохранены.
- Главное меню позиционируется поверх страницы: открытие больше не расширяет шапку фиксированной высоты. Внутри — простые пункты без отдельных обводок; ширина ограничена экраном.
- Браузерная проверка managed preview: 390×844 и 320×740; вход через меню, раскрытие игрока, ручное обновление с сохранением раскрытия. Меню и показатели визуально помещаются, вложенных кнопок нет. Раскрытие не отправляет запросов.
- Проверка синтаксиса и четыре интеграционных теста `tests/test-mode.test.js` прошли. Полное прохождение игры повторно не запускалось: игровая логика не менялась.
