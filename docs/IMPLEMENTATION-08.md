## 2. Демонстрация без прокачки

~~~sh
node server.mjs
~~~

Открыть http://127.0.0.1:3000, создать предложенный синтетический профиль, нажать **«Начать смену»**. Предварительные баллы не нужны. «Класс, время и режим» раскрываются только при необходимости; по умолчанию включено обучение. Для жюри безопаснее сначала показать ранний маршрут, затем отличающийся исход.

### Ранний безопасный путь

1. Начать приёмку → сверить карточку стандарт-класса.
2. Открыть обращение у мест 18–19 → уточнить и пообещать вернуться.
3. Вернуться к обзору → осмотреть салон.
4. Открыть проход → обеспечить свободный проход одним из двух допустимых действий.
5. Вернуться к обращению → проверить сведения и передать запрос коллеге.
6. Дождаться рабочего события: коллега подтверждает получение, ещё не исполнение.
7. Проверить исполнение и сообщить результат **пассажиру у места 18** → завершить смену.

Итог: лояльность 85, безопасность 90, 70 баллов эпизода, зачёт. После первого отмеченного разбора — до 20 XP. В отдельной заранее начатой соревновательной попытке тот же полный результат даёт 100 СП.

### Другие исходы той же смены

Для позднего пути: приёмка → обещание → проверка/передача → ожидание. На шаге 4 сначала приходит подтверждение коллеги, затем ухудшается ситуация в проходе. Feedback можно читать без таймера; **«Продолжить» открывает срочную сцену и запускает окно одновременно**.

| Решение в срочной сцене | Последующее действие | Лояльность / безопасность | Баллы эпизода | Зачёт |
|---|---|---|---|---|
| Обеспечить свободный проход | Вернуться к пассажиру у места 18 | 85 / 75 | 60 | Да |
| Продолжить обслуживание, оставив проход | Вернуться к пассажиру у места 18 | 85 / 35 | 50 | Нет: unsafe_deferral |
| Не принять решение до deadline | Вернуться к пассажиру у места 18 | 85 / 40 | 50 | Нет: critical_timeout |

Критическая ошибка запрещает зачёт/СП, но не уничтожает историю и возможность полезной учебной практики. Ответ пассажиру у места 19 не закрывает обещание пассажиру у места 18. Просрочка рабочей задачи фиксируется один раз; поздний правильный возврат закрывает задачу, но не возвращает потерянную лояльность.

Второй вариант — **«Свободный проход и неверная памятка»**. Багажа в проходе нет: требуется проверить и исправить конкретную информацию выбранного класса. Не нужно механически искать ту же угрозу или выбирать действие из другой формы. Эта форма не смешивается с blocked-aisle в рейтинге.

Прочитан исходный слайд 10: materials/Датасет.zip → photo_2026-09-20_15-09-56.jpg. SHA-256 извлечённого файла:

~~~text
b8c0cdbac9016cd25ac50251b9693c3c4343f83e579f1909aaa84aa1719a6897
~~~

| Класс | Проверяемый факт из проектного слайда | Что действительно меняется в игре |
|---|---|---|
| Стандарт | Компоновка 3 + 2; бистро предусмотрено в одном вагоне | Проверка схемы и исправление обещания бистро в каждом вагоне |
| Комфорт | Компоновка 2 + 2; игровая комната в одном вагоне | Исправление неверного обещания комнаты в любом вагоне комфорт-класса |
| Бизнес | Компоновка 2 + 2; шаг 980 мм | Замена ошибочно приложенной схемы первого класса |
| Первый | Компоновка 2 + 1; проход 650 мм | Замена ошибочно приложенной схемы бизнес-класса |

Источник используется **только для проектных сведений**. Из него не выводятся утверждённые эксплуатационные нормы, состав включённых услуг, цены или гарантии перевозчика. Остальные документы DOC/PDF из ZIP в этой реализации не использованы как якобы прочитанные нормативные источники. Диалоги, численные эффекты, сроки, правила сценария и рубрика авторские, основаны на утверждённом GAMEPLAY и помечены synthetic-requires-methodologist. Содержательная проверка перевозчиком остаётся необходимой.

Содержание отделено от двигателя, имеет версию и SHA-256. При публикации проверяются обязательные поля, семь критериев, четыре разные политики, две поддерживаемые формы, безопасная альтернатива, полный причинный разбор, числа и графы. shift-2 — фиксированный контроллер этого эпизода: произвольная новая структура переходов требует новой версии движка, а не загрузки непроверенного кода из JSON.

## 4. Хранение и восстановление

Миграция повышает PRAGMA user_version с 1 до 2 транзакционно и добавляет таблицы shift_*, practice_*, motivation_*, competition_attempts, debrief_acks, legacy_awards и операторский аудит. Старые runs/results/scenarios остаются, включая активные v1-дедлайны. Для восстановления неизвестной будущей схемы сервер отказывает, а не сбрасывает базу.

Перед обновлением production-подобной среды остановить сервер и скопировать файл SQLite вместе с оставшимися WAL/SHM, если они существуют. Не копировать один основной файл во время записи. Проверить обновление на копии. Для отката восстановить резервную копию и прежний код вместе; старый бинарный код не следует запускать на новой схеме.

Внутри BEGIN IMMEDIATE сохраняются действие, рабочий шаг, очередь, факты, журнал, checkpoint, итог и квитанция. Accepted error-timeout — особый подтверждённый переход: результат сохраняется даже при HTTP 409. XP/цель начисляются позже отдельной транзакцией first debrief-ack, поэтому сбой после окончания смены не теряет право на разбор и не дублирует XP.

Рабочий профиль остаётся синтетическим. Нет SSO и восстановления идентичности после утраты сессии; это ограничение существующей демонстрационной авторизации, а не отказ сохранения БД. Истечение сессии не предоставляет другому профилю доступ к попытке.

## 5. Локальное управление содержанием

~~~sh
node scripts/shift-content.mjs validate
node scripts/shift-content.mjs export shift-candidate.json
node scripts/shift-content.mjs validate shift-candidate.json
node scripts/shift-content.mjs publish data/reis400.sqlite shift-candidate.json
node scripts/shift-content.mjs list data/reis400.sqlite
node scripts/shift-content.mjs disable data/reis400.sqlite text-shift-demo shift-content-1
node scripts/shift-content.mjs enable data/reis400.sqlite text-shift-demo shift-content-1
~~~

Изменять уже опубликованные байты под тем же id/version запрещено. Для изменения нужно увеличить version; автоматическая публикация при запуске не перезаписывает старое содержание и не включает обратно отключённую версию. Новая неделя закрепляет новый пакет; текущая неделя не меняет форму на ходу. Устаревшая версия остаётся доступной для восстановления/точного воспроизведения начатых попыток.

При подтверждённом техническом сбое локальный оператор может использовать:

~~~sh
node scripts/shift-content.mjs compensate data/reis400.sqlite PROFILE_UUID RUN_UUID "Описание подтверждённого технического сбоя"
~~~

Сначала попытку нужно завершить/прервать обычным способом. Команда доступна только оператору с файловым доступом, в текущей неделе **до принятого debrief-ack**. Она записывает technical_replacements/audit, исключает старый результат из СП и освобождает тот же ordinal для замены; повтор одобрения ничего не удваивает. Пользователь сам запросом API лимит не обнуляет. Ретроактивное изменение уже выданного постоянного XP/наград после подтверждённого разбора не автоматизировано: для такого случая нужен отдельный операторский процесс. Это явное ограничение, не скрытая третья бесплатная попытка.

## 7. Что не заявляется готовым

Игра — воспроизводимый законченный хакатонный MVP с одним сквозным эпизодом, а не промышленная аттестационная система. Не проведены методическая валидация рубрики перевозчиком, наблюдаемое тестирование 3–5 реальных пользователей и отдельная приёмка #27; нет корпоративного SSO, реального HR-подключения, нагрузочного/длительного пилота или подтверждённого улучшения профессиональных навыков. Серверный адрес публичного развёртывания не появляется от одного коммита: статический хостинг не заменяет backend.

Backlog #23 — турниры, streak, множители XP, платные восстановления, командные квесты и поведенческий matchmaking — намеренно не включён. Семь критериев не превращаются в диагноз профессиональной пригодности. Новые рейтинги не смешивают условия и не наполняются ботами ради красивого списка.
