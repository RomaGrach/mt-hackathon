# API v2 — полноценная смена и мотивация

Рабочая реализация задачи #26. Схемы запросов и публичных ответов: [OpenAPI 3.1](openapi.json). Операции v1 сохранены в [API.md](API.md). Версия приложения — 2.1; движок смены — shift-2; начисления — gamification-1. Это разные версии, а не один номер.

## Доступ

Все операции ниже требуют текущую HttpOnly-сессию reis_session. Создать синтетический профиль — POST /api/session с телом {}. Для изменений необходимы Content-Type: application/json и X-Reis-Client: web. Origin, лимиты тела, rate limit и защита от CSRF те же, что у v1. Идентификатор чужой попытки возвращает 404, а не её наличие/состояние. Ни публикации, ни операторская компенсация через HTTP игрока не доступны.

## Смена

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/v2/catalog | Опубликованные смены, классы, политики времени и учебные варианты без внутренних графов |
| POST | /api/v2/runs | Создать закреплённый брифинг, 201 + ShiftPublic |
| GET | /api/v2/runs/:id | Текущее состояние; просроченное окно завершается сервером |
| POST | /api/v2/runs/:id/commands | Одна команда, 200 + receipt/run |
| GET | /api/v2/runs/:id/result | Результат всей завершённой смены |
| GET | /api/v2/runs/:id/replay | Точная проверка журнала, без нового run и наград |
| POST | /api/v2/runs/:id/replay | Новая учебная ветка до указанного рабочего события, 201 |

Пример создания:

~~~json
{
  "requestId": "a-client-generated-unique-id",
  "scenarioId": "text-shift-demo",
  "mode": "training",
  "timingPolicyId": "standard",
  "serviceClass": "standard",
  "variantId": "blocked-aisle"
}
~~~

mode: training или assessment. serviceClass: standard, comfort, business, first. variantId можно прислать только в training. Для несоревновательной проверки вариант выбирает сервер. Политики standard/extended/untimed означают 20 000 / 200 000 / null миллисекунд; они фиксируются при создании и не меняются посреди попытки. Без времени критерий timely-safety получает not_assessed, earned=null, possible=null — не ноль баллов за медленную реакцию.

Для соревнования добавляется competitionSlotId: shift, mode=assessment, стандартные класс и время, без variantId. Требуется предварительное добровольное вступление в текущий период. Содержание берётся из закреплённого недельного пакета, а не из произвольно новой публикации. В брифинге номер попытки ещё не расходуется: резерв ordinal 1/2 происходит при begin. После двух номеров можно продолжать обучение, но не начать третью соревновательную попытку.

Пример команды:

~~~json
{
  "requestId": "another-client-generated-id",
  "revision": 0,
  "command": { "type": "begin" }
}
~~~

Ответ содержит receipt {requestId, revision, acceptedAt} и run. Клиент берёт действие только из актуального run.actions и передаёт разрешённые поля; points, elapsed, deadline, band, ordinal, критерии и скрытые признаки не принимаются.

| type | Дополнительные поля command | Рабочие шаги |
|---|---|---|
| begin, continue, overview, pause, resume, finish, abort, wait | Нет | wait: 1; остальные: 0 |
| focus | incidentId | 0 |
| inspect | zoneId, actionId | 1 |
| choose | incidentId, sceneId, actionId, windowId; incidentId/windowId могут быть null | 1 |
| hint | hintId | 0; только обучение |

Неизвестные поля или некорректные tagged-команды — 400. Команда правильного формата, но недоступная в текущей сцене, — 409 WRONG_PHASE. Один профиль может иметь только одну активную попытку, включая v1, v2 и paused.

## Время, revision и квитанции

Транзакция BEGIN IMMEDIATE сериализует проверку, действие, события, checkpoint, результат и квитанцию. Для авторизованного запроса с корректным requestId существующая квитанция проверяется до повторного применения revision/времени. Тот же ключ и тот же запрос возвращают тот же HTTP-статус и тело. Другое тело/путь с тем же ключом — KEY_REUSED. Ключи независимы у разных профилей; квитанции хранятся до удаления профиля, не очищаются через неделю.

Клиент обязан сохранить точное тело до отправки и при сетевой неопределённости повторить его, а не создать новый ключ или подменить revision. После восстановления квитанции следует GET текущего состояния: квитанция по определению может описывать уже прошедшую ревизию. Оба клиентских pending-хранилища очищаются при 401/выходе/удалении профиля.

acceptedAt определяется сервером после захвата транзакции, не раньше последнего наблюдённого серверного времени этой попытки. Чтение и переключение дел не расходуют шаги. Критический таймер появляется только после continue из feedback: описание срочной сцены, варианты и deadline публикуются вместе. Pending не раскрывает deadline, варианты или идентификатор ещё не открытого окна.

При acceptedAt >= deadline сервер фиксирует timeout **до** проверки устаревшей revision. Поздний choose не выполняется; возвращается 409 DEADLINE_EXPIRED с run уже после timeout. Этот 409 коммитит последствие и точную квитанцию, а не откатывает время. GET, фоновый sweep и повторная отправка используют ту же функцию и не дублируют штраф. Ошибка STALE_REVISION сама по себе не разрешает автоматически заново отправить выбор.

Training-пауза сохраняет remainingMs и activeElapsedMs. Возобновление использует остаток, не полный новый срок. Подсказка в открытом срочном окне приостанавливает обучение. В assessment pause/hint не предлагаются и не принимаются. Пауза личной недельной цели — другая настройка; она никогда не останавливает игровой таймер.

## Публичное состояние и результат

ShiftPublic возвращает schemaVersion, engineVersion, id, scenarioId, contentVersion, revision, mode, timingPolicy, status, phase, stage, step, context, обе scales, только обнаруженные actors/incidents/observations/tasks, текущую scene, доступные actions, feedback, безопасную проекцию criticalWindow, видимую history, result и serverNow. В обучении возможен hintText. После завершения добавляется debrief со статусом подтверждения и первой квитанцией.

Наружу не выдаются внутренние flags, очередь scheduledEvents, undiscovered IDs/число скрытых инцидентов, ключи ответов, полный граф, rubric до завершения или список будущих событий. Публичный результат после завершения раскрывает критерии и объяснения намеренно — для обучения, не для защиты экзамена от заучивания.

Result — один на ShiftRun, не отдельные результаты каждого Incident/Task. Он включает закреплённые версии и comparisonGroup, обе итоговые шкалы, passed/reasons, критические ошибки с evidenceEventId, критерии earned/possible/status, episodePoints, возможный максимум, историю причин/альтернатив, происхождение ветки, признаки помощи/технического сбоя и раздельный результат рейтинга.

rankingEligible=false и rankingIneligibleReason объясняют, почему попытка не даёт СП. episodePoints — не XP и не СП. Критическая ошибка не компенсируется другими баллами. Показатели не являются оценкой профессиональной пригодности: notForEmploymentDecisions=true.

Exact replay использует начальный снимок, закреплённые байты содержания, записанные команды и acceptedAt. При несовпадении хеша — CONTENT_INTEGRITY; при отсутствии версии — CONTENT_VERSION_MISSING; неподдерживаемый движок — UNSUPPORTED_RUN_VERSION; несовпадение воспроизведения — REPLAY_MISMATCH. Ни одна ошибка не подменяет старое содержание новой версией.

POST replay принимает {requestId, originEventSeq}. Доступны только собственные записанные рабочие действия/timeout. Создаётся новый training-run с origin {runId, originEventSeq}, исходный результат не переписывается. Уже наблюдавшиеся факты наследуются; критерий не считается новым свидетельством исправления, если он просто унаследован. Критическое окно новой ветки открывается заново только после continue.

## Мотивация

| Метод | Путь | Основной контракт |
|---|---|---|
| GET | /api/v2/motivation | XP, уровень практики, weeklyXP, период/пакет/участие, цель, навыки/evidence по одинаковым условиям, nextReview, награды, история/архив |
| POST | /api/v2/motivation/preferences | requestId и необязательные goalDays (1/2/3), paused, automaticNotices |
| POST | /api/v2/periods/:periodId/entry | requestId, action join/withdraw |
| POST | /api/v2/results/:id/debrief-ack | requestId; первый подтверждённый разбор и транзакционный XP-кредит |
| GET | /api/v2/leaderboards | scope=crew/depot/company, periodId, offset>=0, limit=1..50 |

Полный полезный разбор — до 20 XP на семейство в неделю, ветка — 10 с возможностью добрать до 20. Первый ack данного run глобально один: повтор на другой неделе не создаёт ещё кредит. Максимум первых пяти семейств за неделю; новые семейства сверх лимита не получают XP, апгрейд уже принятого 10→20 разрешён. Реальный каталог MVP содержит одно семейство — доступный предел 20 XP, не обещанные 100 за отсутствующие сценарии. Некритичная или критичная учебная ошибка сама по себе не лишает полезного XP; abort, технически непригодный результат и нулевое число решений не засчитываются.

XP использует неделю первого ack. День личной цели использует московскую дату завершения, только если ack в той же неделе. Несколько разборов в один день — один день. Снижение цели после первого учтённого дня действует со следующей недели. Уже выполненная цель не разрушается изменением настройки: новая цель применяется в следующем периоде. Счётчик успешных недель не является streak; пропуск не стирает прошлые недели.

Период — [понедельник 00:00, следующий понедельник 00:00) Europe/Moscow. active СП истекают, XP/история/достижения остаются. В одном слоте максимум 100 СП: floor(100 * earnedUnits / possibleUnits), лучший пригодный результат двух попыток, не сумма. Пересечение endAt не даёт СП ни в старую, ни в новую неделю.

Вступление закрепляет организацию и поток starter/main/returning. Starter — менее двух активных завершённых соревновательных недель; возвращающийся поток требует основного потока и 28 дней без полезной практики. returnPending фиксируется до возобновления практики и сохраняется до активной недели возвращения; простой пропуск недели его не расходует. Места публикуются только при пяти положительных сопоставимых результатах в своей группе. Нули, другие классы/варианты/политики/пакеты/потоки не подмешиваются. Ничья — общие места 1,1,3; me доступен вне top-50.

Архив хранит первоначальные места и размеры групп. Поздний withdraw скрывает строку, удаление профиля удаляет его данные из архива; места оставшихся участников не пересчитываются. Закрытая неделя не допускает повторного join.

ReviewItem выбирает критическую ошибку, затем невыполненный обязательный критерий, другой невыполненный критерий, успешную практику. Одно открытое повторение на семейство; подсказка не закрывает его. Нужно новое свидетельство выполнения критерия и первый ack. Untimed не исправляет критерий своевременности автоматически. За исправление нет отдельного XP/SP-бонуса.

Автоматические in-app сообщения: максимум одно за визит и три в неделю, визит после отсутствия минимум 30 минут. Приоритет: актуальное истечение СП, новый сценарий, недельная цель/соревнование, повторение. Нет прерывания активной смены; пауза/отказ отключают автоматические показы, но не inbox. Уведомление об истечении создаётся только при положительных СП в последние 48 часов до endAt; прошедший срок не используется для нового автоматического напоминания.

## Совместимость и интеграция

GET /api/bootstrap добавляет motivation и shiftCatalog, сохраняя legacy profile/catalog. GET /api/runs/:id умеет прочитать и восстановить существующую v2-смену для старого маршрута фронтенда; изменение v2 через decision/continue v1 отвергается USE_V2_API.

GET /api/profile/export включает motivationV2 и notForEmploymentDecisions. Существующие read-only интеграционные API сохраняются: profiles добавляет practiceV2, results содержит версионированные документы v1/v2. Потребитель обязан различать schemaVersion/engineVersion, а не складывать прежние points с episodePoints/XP/СП. Реальная корпоративная интеграция, SSO и использование для зарплаты не реализованы.

## Локальный оператор

Команды публикации/отключения и подтверждённой технической замены описаны в [IMPLEMENTATION-08](IMPLEMENTATION-08.md). Права оператора — доступ к серверной машине и файлу БД, не роль, доступная игроку через API. Отключение публикации запрещает новые попытки, но не ломает продолжение/разбор старых.
