# Аудит текущего интерфейса

Проверено локально 26.09.2026 на `77c470ff29bb3c7ee334ffa098ba0223cb0e330a`. Запущен исходный `server.mjs` на 127.0.0.1:4310 с отдельной SQLite `:memory:`. Рабочая БД не использовалась. Frontend приложения не изменялся.

## Охват

В браузере пройдены все пять модулей до результата: conflict (5 решений), medical (5), delay (5), service (4), baggage (4). Осмотрены вход, главная, брифинги, выборы, последствия, результаты, профиль, аналитика, достижения, история, повтор развилки, уведомления, три области рейтинга. Повтор развилки проверен как практика. Это обзор всех основных поверхностей, не перебор всех веток сценариев.

Основные размеры: 1440×900 и 390×844; дополнительно главная проверена на ширинах 1280, 1024, 768, 320. Использован установленный Edge через Playwright, headless. Это эмуляция размеров, не проверка физического смартфона. Во время пяти прохождений и обзора поверхностей ошибок JavaScript не получено. Сырые результаты: [audit-runtime.json](evidence/audit-runtime.json), [first-home-geometry.json](evidence/first-home-geometry.json). Изображения — в [evidence](evidence/).

Три подписанных нижних раздела: Главная, Профиль, Рейтинг. Слова «К обстановке» и «Открыть дело» для игровых переходов. Внутренняя цель нажатия 48 px. |

Виден тот же эффект на mobile. | Отдельная зона вопроса; 8 px до пояснения, 20 px до вариантов, 12 px между вариантами, 16–20 px внутри. Размеры задаются компонентом, а не случайными внешними margin. |

В предложении высота от содержимого; декор отдельный, CTA в нормальном потоке. Не выдавать гипотезу о причине за установленное воспроизведение. |

## Приоритетные проблемы

| Приоритет | Экран / проблема | Что меняем |
|---|---|---|
| P1 | Главная предлагает один выбор модулей трижды: hero, маршрут из 5 кнопок, 5 карточек. 11 входов в один каталог конкурируют с прогрессом и челленджем. | Один главный вход «Начать / Продолжить рейс». Прогресс — кратко. Точечная практика — второй уровень. |
| P1 | «Начать смену» фактически запускает отдельный модуль. «Следующая ситуация» иногда означает следующий узел того же диалога; «К смене» ведёт в каталог. | Явно разделить рейс, обстановку, конкретный инцидент и локальное последствие. Полный рейс требует будущей модели v2. |
| P1 | На 390×844 первый ответ начинается около нижней части экрана. Декоративный вагон и крупная карточка контекста занимают значительную часть первого экрана. | Убрать большую иллюстрацию из локального решения. Контекст 2–3 предложения, две шкалы перед сценой, варианты сразу после вопроса. |
| P1 | На mobile шкалы и ресурс экипажа идут после списка вариантов. Игрок может выбрать, не увидев состояние. | Две компактные шкалы над сценой; другие дела в раскрываемой сводке. Очки не конкурируют с рабочим выбором. |
| P1 | При ширине 320 px главная имеет горизонтальную прокрутку. | Одноколоночный reflow, `min-width:0`, перенос текстов, отсутствие фиксированной ширины карточек и inline-строк с несколькими неделимыми элементами. |
| P1 | Параллельность пока отсутствует как пользовательский цикл: текущая игра проходит один граф. | Две независимые известные проблемы в одном рейсе, один фокус сцены, сохранённое адресное обещание. Это проект новой версии, не косметическая замена карточек. |
| P2 | Брифинг одновременно объясняет пороги, сервер, правила рейтинга, ресурс, длительность, версию и число сцен. | Три простых правила; выбор режима и времени; правила оценки и технические сведения по запросу. |
| P2 | Обычный выбор сразу отправляется. Случайное касание длинной карточки при прокрутке трудно исправить. | В обычной сцене выбор + явное выполнение в том же экране. В коротком срочном окне сохранить прямое действие и прямо подписать это. Гипотеза требует проверки людьми. |
| P2 | «Серверный прогресс», версия сценария и многочисленные очки постоянно занимают внимание. | Статус сохранения показывать при изменении/ошибке; версии — в подробностях разбора. Сводить мотивацию в профиль. |
| P2 | Последствие выделяет универсальный заголовок и символ вместо конкретного изменения мира. | Заголовок «Проход снова свободен», фактические изменения шкал, «Что ещё изменилось», следующий переход. |
| P2 | Профиль длинный: навыки, советы по каждому, статистика, динамика, история, бонусы, достижения. | Первым экраном последнее наблюдение и следующая практика; история и детали раскрываются по запросу. Разделить критерии, XP, СП. |
| P2 | Незачёт/критическая ошибка и общая сумма баллов могут создавать противоречивый акцент. | Итог начинается с исхода и причины. Высокий XP не окрашивает критический провал как успех. |
| P3 | Избыточные капительные подписи и фразы «скорость решения имеет значение» усиливают ощущение гонки даже там, где таймера нет. | Короткие спокойные заголовки; свободное чтение обозначено; время только при действительной срочности. |

P1 — мешает пониманию/доступу к действию; P2 — увеличивает усилия/ошибки; P3 — визуальный шум. Это экспертная оценка интерфейса, не результаты пользовательского исследования.

## Что сохранить

- Раздельные сцены и последствия: человек успевает прочитать результат до следующего таймера.
- Обе учебные шкалы, причинный разбор и возможность практики из истории.
- Узнаваемые тёмный фон и сиреневый акцент.
- Реальное сохранение текущей версии приложения и разграничение практики/зачёта. Новый прототип только изображает будущий UX.
