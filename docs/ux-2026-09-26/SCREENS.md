# Спецификация макетов

Восемь основных экранов, desktop и mobile, плюс вспомогательные состояния. Макеты и текст — предложение для согласования. [Открыть обзор](index.html). [Все PNG](screens/).

| № / экран | Главная задача | Иерархия и основной переход |
|---|---|---|
| 01 Главная | Начать или продолжить практику | Один hero с CTA → краткая недельная цель/прогресс → точечная практика. Рейтинг не перехватывает первый запуск. |
| 02 Рейс / обстановка | Понять мир и выбрать приоритет | Стадия и рабочий шаг → две шкалы → 2–3 предложения наблюдения → осмотр → известные дела → обещание. Ничего скрытого в счётчике. |
| 03 Открытый инцидент | Понять конкретную проблему | Явный возврат → название/место/статус → шкалы → короткая сцена → 2–4 варианта; другие дела компактно рядом/над сценой. |
| 04 Выбор действия | Осознанно выполнить вариант | Тот же экран, отмеченный вариант и активная кнопка «Выполнить действие». Нет отдельного ненужного перехода или модального подтверждения. |
| 05 Результат действия | Увидеть последствия и изменения других дел | Конкретный результат в заголовке → наблюдаемый факт → шкалы до/после → «Что ещё изменилось» → объяснение в обучении → возвращение/срочный сигнал. |
| 06 Итог рейса | Понять исход и следующий шаг практики | Зачёт/нужна практика и причина → две шкалы → наблюдённые критерии → причинная история → новая практика. XP/СП отдельно. |
| 07 Профиль | Увидеть личную историю и полезную практику | Последнее сопоставимое наблюдение → история с разбором → опыт практики и достижения → рекомендация. Без попыток — «не оценено». |
| 08 Рейтинг | Сравнить допустимые результаты по желанию | Неделя/пакет/группа → бригада/депо/компания → таблица СП → условия участия. По умолчанию участие выключено. |

На мобильном главная навигация подписана: Главная / Профиль / Рейтинг. В игровом фокусе её заменяет возврат к обстановке, чтобы случайно не увести человека из задачи. Прокрутка допустима; уменьшение текста ради «всё в один экран» не является целью.

## Дополнительные визуальные состояния

Открываются в переключателе экрана [обзора](index.html):

- **Брифинг:** выбор обучения/проверки себя; 20 / 200 секунд / без ограничения; opt-in соревнования только при проверке себя.
- **Приёмка:** содержательная сверка учебной карточки; результат становится известным фактом. Не чекбокс согласия.
- **Срочный сигнал:** отображается на feedback. Отсчёт ещё не идёт, варианты будущего решения не показаны.
- **Критическая сцена:** один таймер, один фокус, два стабильных действия; посторонние переходы заблокированы.
- **Пауза:** явное состояние с остатком, resume продолжает его. Только обучение. Подсказка сначала включает учебную паузу.
- **Timeout:** одно последствие и причина незачёта; исход не исчезает после успешного другого действия.
- **Незачёт:** критическая причина прежде мотивационных наград. Непройденное можно повторить как новую практику.
- **Потеря ответа:** выбранное действие названо, показано ожидание подтверждения, CTA «Проверить состояние и восстановить». Это визуальная демонстрация, не сеть.
- **Пустой профиль:** спокойное приглашение в первый рейс, никаких нулевых процентов профессиональных навыков.
- **Уведомления:** отдельная лента вместо перекрывающих игровой экран сообщений.
- **Досрочное завершение:** достигается из обзора через подтверждение; прерывание не маскируется под критическую ошибку, XP/СП 0.

## Контракт состояний для будущей реализации

Следующие состояния описаны как требования к реализации, но не реализованы как настоящие сетевые/серверные механизмы в макете:

| Состояние | Видимый текст / действие | Правило |
|---|---|---|
| Первичная загрузка | «Загружаем ваш рейс…» + скелет прежнего размера | Не мигать пустым новым профилем |
| Команда отправлена | «Подтверждаем действие…», выбранная карточка остаётся | Блокировать повторный выбор до результата, не менять высоту панели |
| Ответ потерян | «Проверяем, принят ли ваш выбор» → восстановить | Повторять тот же requestId; не начислять второй шаг |
| Offline в срочном окне | «Нет связи. Срок решения продолжает действовать» | Нельзя обещать локальную паузу сервера |
| Устаревшее состояние | «Ситуация обновилась. Прочитайте изменения и выберите действие снова» | GET актуального состояния, не отправлять прежний выбор с новой revision автоматически |
| Профиль недоступен / 401 | «Сессия завершена. Войдите, чтобы продолжить» | Если авторизация демо не восстанавливается, явно описать создание нового профиля; не обещать возврат неподдерживаемого доступа |
| Старая версия недоступна | «Этот разбор временно недоступен» → вернуться в историю | Не подставлять новую версию сценария вместо старой |
| Нет доступного соревнования | «Пакет недели пока не опубликован» → практика | Не выводить вымышленные реальные места или счёт 0 как измеренную способность |
| Лимит соревновательных попыток | «Обе попытки использованы. Практика остаётся доступной» | Не блокировать обучение; попытка резервируется до раскрытия содержания |
| Лимит 16 шагов | «Учебная попытка завершена: остались открытые дела» | Явный итог по каждому делу, без исчезновения обязанностей |

## Микротекст

| Сейчас / нежелательно | Предлагается |
|---|---|
| «Моя смена» как одновременно каталог и текущая игра | «Главная» и «Текущий рейс» |
| «Следующая ситуация» | «К обстановке в вагоне» / «Перейти к срочной ситуации» |
| «Ваш выбор изменил ситуацию» | «Проход снова свободен» / «Коллега принял задачу» |
| «Очки компетенций» как единая сумма | «Учебные критерии», «Опыт практики — XP», «Сезонные очки — СП» |
| «Закрыто» после отправки запроса | «Запрос отправлен» → «Коллега принял задачу» → «Исполнение проверено» |
| «Скорость» вне срочного окна | «Своевременность действий» |

Рабочие варианты не называются «правильный/неправильный» до выполнения. В обучении появляется объяснение результата, в проверке себя — только наблюдаемое последствие и шкалы до финального разбора.

## Согласование перед frontend

На одном обсуждении нужно принять: (1) двухуровневый обзор/инцидент; (2) выбор + выполнение в обычной сцене и прямое действие в срочной; (3) расположение других дел/обещаний на телефоне; (4) визуальную плотность и типографику. Названия и содержание класса обслуживания проверяются отдельно по данным заказчика. Переносить неподтверждённые условия класса в макеты как факты нельзя.

Предложение короткой проверки на 3–5 людях: без объяснения попросить начать рейс; найти известное дело; открыть/вернуться; заметить второе дело после осмотра; объяснить отличие передачи и завершения; найти обещание; после итога назвать причину результата. Наблюдать затруднения и случайные нажатия, а не только спрашивать «нравится ли». Такая проверка в этой работе не проводилась.
