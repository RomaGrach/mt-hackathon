# Базовая дизайн-система

Предложение, 26.09.2026. Тёмная тема сохраняет узнаваемость РЕЙС 400. Сиреневый — действие и выделение, а не знак успешности. Макеты используют локальный Segoe UI; загрузка шрифтов и сети не нужна.

## Компоненты

**Кнопки.** Основная — одна ведущая цель экрана; min-height 48, radius 12, padding 12×18, текст 15–16, перенос разрешён. Вторичная — поверхность и обводка. Текстовая — возврат/вспомогательное действие, зона нажатия не меньше 44 px по высоте. На мобильном экране главный CTA по ширине контейнера. Состояния: default, hover, focus (3 px + offset 4), selected, disabled с текстовым объяснением, pending «Подтверждаем действие…». Disabled не использовать как единственное объяснение недоступности.

**Карточка инцидента.** Статус → конкретное название → место и одна строка контекста → стрелка. Не более двух открытых инцидентов в MVP. Вся карточка — одна кнопка; внутри нет вложенных кнопок. «Вернуться к пассажиру» — отдельная карточка обязанности, связанная с адресатом.

**Карточка действия.** Глагол + объект; дополнительная строка только если уточняет объём. Радиомаркер показывает выбор, не оценку правильности. Обычный выбор подтверждается кнопкой «Выполнить действие» без модального окна. Критический вариант выполняется нажатием сразу; правило подписано перед кнопками.

**Шкалы.** Две равноправные компактные шкалы: лояльность и безопасность, 0–100 условных единиц. Не `% реального риска`. На feedback — до → после и фактическая дельта. XP не показывается третьей рабочей шкалой.

**Статусы.** «Нужно решение», «Требует внимания», «Запрос отправлен», «Коллега принял задачу», «Исполнение проверено», «Выполнено», «Завершено с ошибкой». Срочность и выполнение — разные свойства. Активный экран не является статусом инцидента.

**Таймер.** Только один, рядом со сценой и выбором. Показывает оставшиеся секунды числом; не прыгает, не мигает, не переставляет ответы. До запуска — явно «Отсчёт ещё не начался». После нуля — неизменяемое последствие, без отрицательных секунд и повторного старта. Обучение: пауза с остатком; проверка: без паузы. Выбор 20 / 200 секунд / без ограничения до начала. Значения взяты из проектного примера, не являются отраслевым нормативом.

**Сообщения и слои.** Обычный статус соединения — inline-блок. Уведомления о наградах не всплывают поверх критического выбора. Небольшой toast не перекрывает CTA. Диалог только для прерывания/удаления, с возвратом фокуса; viewport padding ≥16, max-height по доступной высоте, собственная прокрутка при необходимости. Cookie-баннер в показанной игре не нужен; если появится, он должен иметь управляемый размер и не лежать поверх кнопок.

**Адаптивность.** 1440 → 1024 → 768 → 390 → 320. В игре на mobile нет фиксированной панели поверх вариантов: CTA идёт в потоке. Нижнее глобальное меню только вне рабочего фокуса; под него предусмотрен padding + safe-area. Декор не задаёт высоту контейнера и не обрезает текст.

## Доступность и границы

Внутренняя цель крупных действий — 48 px; это наше продуктовое решение. [W3C SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) описывает минимальные размеры с исключениями. Проверка переноса ориентируется на [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html); отдельная проверка увеличения текста также необходима. Варианты времени и пауза проектируются с учётом [W3C Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html). Источники просмотрены 26.09.2026.

Использовать нативные button/radio/select/details, видимый focus, логичный Tab-порядок, заголовок после перехода, доступные имена и live-region для принятого результата. Не озвучивать каждую секунду таймера; достаточно уведомления при запуске, важном пороге и истечении. Уважать reduced-motion. Полное соответствие WCAG этим макетом не заявляется; нужны screen reader, реальное масштабирование, пользовательские и аппаратные проверки.
