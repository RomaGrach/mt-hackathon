# Проверка соответствия Design002 — 27 сентября 2026

Основание: неизменённый `docs/design/design002.md` и уточнение пользователя: не показывать длительность/стоимость действия на кнопках. Сам документ запрещает видимые внутренние сроки; запрет подписей стоимости зафиксирован именно уточнением. Последние согласованные уточнения интерфейса также сохранены: отдельный лог без спойлеров, компактный итог с раскрываемыми подробностями и полная схема вагона.

Проверяемая версия: `design002@1.1.0`, `shift-4`, `mechanicsVersion: 2`. Независимый сабагент `design002_auditor` читает документ и фактический код, не редактирует реализацию и не публикует сайт. Основной агент вносит исправления, затем возвращает их на повторный аудит.

## Цикл проверки

Раунд 1 обнаружил девять действующих расхождений и один латентный дефект условий задач. Раунд 2 подтвердил устранение A1–A10 и не нашёл новых блокирующих расхождений в разделах 1–21. Дополнительное замечание второго раунда — противоречивый текст о таймере в старом сохранении без таймера — исправлено условным выводом сообщения. Финальная независимая сверка после этого исправления: блокирующих замечаний к публикации не осталось.

| ID | Расхождение | Исправление / доказательство |
|---|---|---|
| A1 | Критическая ситуация могла не иметь реального срока | В новом контенте только 60/120 секунд. API отклоняет `untimed`, курс и своя тренировка больше его не предлагают. Проверена критическая связанная ситуация даже в первом уровне |
| A2 | Профилактика последним ходом всё равно давала плохой исход | Предотвращённая запланированная проблема исключается до закрытия остатка и из MAX; причина журнала указывает на выполненную проверку |
| A3 | Остаточные события подменяли причину немедленного провала | Сохраняется первая фатальная причина; остальные последствия учитываются отдельно |
| A4 | Нелетальный критический провал отсутствовал в разборе | Полный список `criticalErrors`, счётчик `criticalFailed`, отметка конкретной проблемы в разборе |
| A5 | Не показаны FACT и MAX | В сводке видны набранные / максимально возможные баллы вместе с нормированной оценкой |
| A6 | Нет шкалы отдельного пассажира | В открытой ситуации показана лояльность пассажира по её адресу; общий HUD сохраняет среднее |
| A7 | Аналитика игнорирует невыполненные обязательства | Профиль включает невыполненные задачи с конкретным последствием и ссылкой на смену |
| A8 | Правильный путь внутри диалога заменялся общей фразой | Поиск лучшего исхода проходит по вложенным репликам и показывает последовательность решений |
| A9 | На кнопках написано «1 ход» | Подписи стоимости полностью убраны; общая модель ходов и отдельный реальный таймер сохранены |
| A10 | Уборка одного участка разрешала проверку другого | Локальные условия привязаны к родительской проблеме; общая подготовка обслуживания остаётся общей |

## Проверки и границы

- Полный набор: 144 теста прошли, `npm run check`, `npm run validate:scenarios`, `npm run validate:shift`, `npm run format:check`, `npm run build:sites` успешны.
- Новые регрессии: `tests/design002-compliance.test.js` (семь составных проверок A1–A10).
- Независимый аудит: 29 профильных тестов плюс дополнительная симуляция 100 смен / 1583 команды, четыре нагрузки, четыре класса, оба реальных таймера и намеренные таймауты. Проверены единственность активной критической проблемы, конечность, диапазон оценки, знаменатель и закрытие задач.
- Три ранее сохранённые смены preview успешно воспроизведены точно: версии 1.0.0, 1.0.2 и 1.0.3. Старые результаты и правила не пересчитываются задним числом.
- Браузер: новая смена, обращение и создание обязательства, отсутствие длительности на кнопках, персональная шкала, итог с FACT/MAX; размеры 390×844 и 320×740 без горизонтального переполнения. Снимок: [экран ситуации](../implementation/design002-compliance-mobile.jpg).

Новые правила относятся к вновь начатым сменам. Ранее начатая смена закреплена за своей неизменяемой версией содержания; для старого режима без таймера интерфейс сообщает это явно. Чтобы проверить новые правила, начать новую смену. Это сохранение совместимости, а не скрытая миграция или сброс прогресса. Результат первой ступени, ранее завершённой без таймера, остаётся отметкой прохождения курса.

Точные длины смен, квоты, коэффициенты, сроки и пороги остаются параметрами балансировки, как предусмотрено разделом открытых вопросов. Аудит соответствия не означает, что любая численная настройка уже оптимальна по пользовательскому плейтесту.
