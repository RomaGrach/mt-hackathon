## Существенные риски перед показом

Доступ к опубликованному демо и совпадение версии не подтверждены. Из среды аудита программный запрос к адресу `/api/health` сайта, указанного в README, вернул HTTP 403 со страницей Cloudflare. Это не доказывает недоступность сайта всем пользователям. Требуется обычный браузер вне сессии владельца, другая сеть и проверенный локальный резерв. Ожидаемый движок обновлённого релиза — shift-4. Изменение GitHub само сайт не публикует.

Достижения и требуемые уведомления нужно показать именно в актуальном продукте. Человеческое понимание решения требует отдельной репетиции, особенно с учётом веса критерия — 6 баллов.

Полная браузерная регрессия не подтверждена. На первоначальном срезе полный прежний набор дал 14 успешных тестов из 48. Разобранные ошибки ожидали прежние формы и карточки. На новом Design002 прошли два сквозных smoke-теста; весь старый набор после обновления повторно не запускался. Его необходимо актуализировать, а не скрывать неуспешные проверки.

## Повторная проверка перед сдачей

Сначала зафиксировать дату и проверяющего, SHA, URL демо и версию опубликованного контента. Для каждого пункта отмечать «проверено», «частично» или «не проверено», а не конкурсные баллы.

- [ ] Чистый вход на опубликованный сайт без прав владельца; локальный резерв действительно запускается.
- [ ] Демонстрация и сдаваемый код соответствуют одному SHA; новые смены используют нужную публикацию Design002.
- [ ] Выполнена приёмка, обнаружена скрытая проблема, показаны разные исходы и влияние решений на обе шкалы.
- [ ] Отдельно показан критический таймер: позднее решение не получает новое время после reload.
- [ ] Завершение и сохранение результата проходят; повтор команды или reload не удваивают очки.
- [ ] Профиль, уровень и три области рейтинга работают на синтетических профилях.
- [ ] Получение достижения/бейджа и требуемые уведомления показаны в актуальной игре, не только найдены в старом коде.
- [ ] Разбор объясняет ошибку и альтернативу; история нескольких смен показывает изменение результата.
- [ ] Участники объяснили движок, очки, время, API и сохранение; самостоятельно изменили пример и запустили тест.
- [ ] API и архитектура соответствуют текущей реализации; ограничения интеграции и масштабирования названы честно.
- [ ] Пакет содержит только разрешённые материалы и синтетические данные; тестовый административный режим явно обозначен.
- [ ] Финальный комплект, доступ проверяющего и подтверждение отправки проверены капитаном отдельно.

Автоматическая часть: установить зависимости `npm ci`, затем выполнить `node scripts/preflight-audit.mjs`. Для нового сквозного браузерного пути — `node scripts/preflight-audit.mjs --browser`; требуется установленный Chromium Playwright или `BROWSER_CHANNEL=msedge`. В PowerShell переменная задаётся как `$env:BROWSER_CHANNEL='msedge'`.

Для полного браузерного набора существует `--full-browser`; он не подменяется smoke-тестом и может выявить перечисленные устаревшие проверки. Автоматическая команда не подтверждает доступ опубликованного сайта, качество защиты командой, экспертную валидацию или выполнение отправки.
