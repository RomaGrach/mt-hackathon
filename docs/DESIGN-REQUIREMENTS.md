# РЕЙС 400 — требования к интерфейсу

Версия 1.0 · 26.09.2026 · [06 / #24](https://github.com/RomaGrach/mt-hackathon/issues/24). Основание реализации: `77c470ff29bb3c7ee334ffa098ba0223cb0e330a`. Это предлагаемое дизайн-решение с кодом и проверками, а не запись о согласовании дизайна пользователями или перевозчиком.

## 1. Границы поставки

Рабочие пять серверных модулей v1 получили новую вёрстку, единую навигацию и восстановление запросов. Новая двухуровневая смена доступна отдельно в `/preview.html`: это интерактивный локальный UX-прототип, а не защищённый зачёт. `src/shift-view.js` принимает PublicRun v2, `src/shift-client.js` готовит транспорт для #26; адаптер пока не подключён к рабочему маршруту. Основное приложение не импортирует локальный сценарий прототипа. Нельзя выдавать успешный тест прототипа за проверку v2-сервера, античита или окончательной рубрики.

Источники решений: [SPECIFICATION](SPECIFICATION.md), [REQUIREMENTS](REQUIREMENTS.md), [DOMAIN-MODEL](DOMAIN-MODEL.md), [GAMEPLAY-HANDOFF](GAMEPLAY-HANDOFF.md), пример [PublicRun](examples/shift-v2-contract.json). Мотивационные правила #23 не заменены новой авторской экономикой: рабочий v1 показывает реальные лучшие результаты, а прототип вообще не начисляет баллы.

## 2. Принципы и трассировка

| ID | Требование и основание | Реализация / критерий проверки |
|---|---|---|
| UX-01 | Начать без обязательного длинного обучения; #24, SPEC §2–3 | Короткий вход, одна рекомендуемая попытка; управление объясняется рядом с действием. Настройки прототипа раскрываются по запросу. Проверка понятности людьми ещё обязательна. |
| UX-02 | Двухуровневая смена; DOMAIN, HANDOFF | Обзор → выбранное известное дело → действие → последствие → обзор. Переключение сохраняет остальные дела и не расходует рабочий шаг. |
| UX-03 | Самостоятельное обнаружение; SPEC §5 | До осмотра нет скрытого B, его названия и счётчика. Осмотр — профессиональное действие, а не бесплатная подсказка. Нормальное наблюдение также возможно. |
| UX-04 | Обещание как адресная Task; DOMAIN | Видны адресат, состояние и срок в рабочих шагах. Ответ другому пассажиру не закрывает задачу. Запрос коллеге, принятие и исполнение различаются текстом. |
| UX-05 | Не раскрывать правильный ответ; #24 | Одинаковые стили вариантов, без зелёной «правильной» кнопки и учебного алгоритма в брифинге. Причина недоступности содержит только уже известные факты. В assessment объяснение-ключ скрыто до итога. |
| UX-06 | Две шкалы и причинный разбор; REQ-F04/F07 | Лояльность и безопасность подписаны числом; после выбора — следствие и изменение, после смены — история причин. Критическая ошибка не отменяется хорошим последующим ответом. |
| UX-07 | Время только в критическом моменте; REQ-F03, DOMAIN | В v2 pending не показывает варианты и не запускает срок до continue. Учебная пауза явная, в проверке отсутствует. Untimed не измеряет скорость. В v1 сохранена существующая серверная политика, не выданная за новую. |
| UX-08 | Единая система вторичных экранов; REQ-F01/F05/F06/F08/F09 | Профиль, достижения, рекомендации, история, аналитика, уведомления, рейтинги бригады/депо/компании сохранены; на игровом экране нет этих панелей. |
| UX-09 | Читаемый мобильный основной путь; #24 | Основной текст 1rem, системные шрифты, вертикальный reflow вместо обрезания. 320 CSS px и отдельная проверка текста 200%. Нельзя скрывать переполнение через overflow-x:hidden. |
| UX-10 | Клавиатура, касание, не только цвет; #24 | Основные кнопки минимум 48 px высотой, варианты минимум 56 px; видимый focus-visible, именованные формы, skip-link, текст статуса. Убраны глобальные клавиши 1–4 без возможности отключения. |
| UX-11 | Loading/error/offline/retry; #24 | Пока неизвестна сессия, не предлагаем создать второй профиль. Ошибка — рядом с началом страницы и кнопкой восстановления, offline не означает паузу. aria-busy и role=status отделены от alert. |
| UX-12 | Идемпотентность и восстановление; DOMAIN §7 | До отправки сохраняется точный запрос в sessionStorage. При сбое хранения игровая мутация не отправляется. NETWORK/таймаут/5xx сохраняют квитанцию; после reload повторяется тот же ключ. Новый выбор блокируется до сверки. |
| UX-13 | Конфликт/другая вкладка/401/версия; DOMAIN §6–8 | Stale не повторяется с новой revision; сначала GET и осмысленный новый выбор. 401 очищает неподтверждённый запрос. Неподдерживаемый PublicRun не заменяется молча другой версией. |
| UX-14 | Слабое устройство и reduced motion; #24 | Нет 3D, видео, внешних шрифтов и зависимости от анимации. Эмуляция и её параметры описываются отдельно от физического устройства; никаких заявлений о проверке всех телефонов. |
| UX-15 | Скорость зависит от мысли, не поиска кнопки; #24 | Отдельно измеряются чтение, поиск управления и принятие решения. Автоматический click-to-ready не является временем человеческого поиска или доказательством понятности. |
| UX-16 | Проверяемая приёмка; #24 | Автоматические тесты, реальные скриншоты браузера и протокол 3–5 участников. Незаполненные результаты людей остаются незаполненными; критические ограничения блокируют окончательную приёмку. |

## 3. Дизайн-система и стандарты

Цвета: фон `#f6f7f3`, поверхность `#ffffff`, текст `#18343d`, вторичный текст `#53656b`, действие `#146b61`, фокус `#10554d`, предупреждение `#97382c`. Скругления не кодируют результат; статус обязательно написан словами. Макет использует одну читательскую колонку в решении и адаптивные карточки в каталоге. Глобальное меню не закреплено поверх контента; ошибка также не перекрывает варианты. Достижение подписано «Получено» / «Пока не получено», график имеет численные значения, таймер не озвучивается каждую секунду.

| Источник | Что требует стандарт | Решение проекта и ограничение проверки |
|---|---|---|
| [WCAG 2.2, 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) | AA: 24×24 CSS px или предусмотренные исключения | 48 px для основных кнопок — более строгий внутренний ориентир, не цитата WCAG. Тест высоты видимых кнопок не является аудитом всех целей касания. |
| [WCAG 2.2, 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum) | Компонент в фокусе не полностью скрыт авторским контентом | Отказ от фиксированных перекрывающих панелей; контрастный контур клавиатурного фокуса. |
| [WCAG, 1.4.10 Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow) | Перестроение контента при ширине, эквивалентной 320 CSS px, с указанными исключениями | Автотест 320 px; увеличение корневого шрифта до 200% — отдельная проверка, не подмена теста 400% browser zoom. |
| [WCAG 2.2, 2.2.1](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable) | Временные ограничения регулируются по условиям критерия; essential exception не распространяется автоматически на любую игру | Разные закреплённые политики времени v2, учебная пауза и untimed; результаты разных политик не смешивать без правил #23/#26. |

Ссылки W3C сверены 26.09.2026. Это выбор проектных ориентиров, а не заявление полного соответствия WCAG. Скринридер, все уровни масштабирования, реальные особенности Safari/Android и педагогическая оправданность длительности критического окна требуют отдельной проверки. Значения 20/40 секунд в прототипе иллюстративны, не профессиональный норматив.

## 4. Состояния, ошибки и интеграция

Полная карта состояний и главные цели — в [USER-FLOW](USER-FLOW.md). Для запроса используются только requestId, revision и разрешённые поля команды. Никогда не передаются клиентские баллы, ответ-ключ или новое время. Повтор полученной квитанции сопровождается GET актуального состояния. API автоматически повторяет только GET и запросы с ключом идемпотентности; создание сессии без такого ключа не повторяется автоматически.

В рабочем v1 имеется одна активная попытка. Восстановление не создаёт «вторую смену» и не сбрасывает серверный deadline. Переключение браузерной вкладки и offline не создают учебную паузу. При исчерпании срока интерфейс получает результат с сервера, а не начисляет штраф самостоятельно. В прототипе всё это моделируется локально и явно обозначено; его sessionStorage редактируем, и он не защищает правильные ответы.

Для #26 нужно подключить ShiftClient к маршруту v2 и подтвердить формы PublicRun.scene/actions/result на реальном endpoint. Renderer ожидает у actions поле command, label и адресные поля команды; available/unavailableReason опциональны. scene: title/speaker/text/prompt; feedback: text/impact, explanation только для обучения; result: title/summary/criticalError/rankingEligible/history. Это конкретизация frontend-адаптера, не заявление, что все эти поля уже опубликованы сервером. Нужны контрактные e2e на выдаваемых сервером данных, четыре класса/варианты из утверждённого содержания и проверка смены без локального сценария. Не загружать preview-state.js в зачётный маршрут.

## 5. Условия окончательной приёмки

Технические результаты и дефекты: [first-session-test](../research/ux/first-session-test.md). Макеты: [design](design/README.md). Отдельные задачи на главный и игровой экран не созданы: обе части находятся в #24. Открыты реальные проверки первого прохождения 3–5 людьми, согласование дизайна и серверная интеграция новой смены #26. До них формулировки «основной путь понятен без инструкции» и «весь выбранный геймплей работает на сервере» не подтверждены.
