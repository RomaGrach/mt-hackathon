# Design 002 — внедрение, баланс и проверка

Источник правил: [design002.md](design/design002.md), GitHub main `fa2972a5ae73d5f5b734338c52687bd10df1accb`.

## Рабочая версия

Новые смены используют `design002@1.2.0`, движок `shift-4`, транспорт API v2. Новая главная, курс, своя тренировка, профиль, рейтинг и администратор подключены к этому движку. Никакие результаты из браузера сервером не принимаются.

`backend/shift-runtime.js` выбирает движок по закреплённой версии содержания. Старые `shift-2`/`shift-3` и их результаты продолжают открываться по старым правилам. Сброса профилей или базы нет. В профиле есть ссылки на прежние смены; прежний XP не объявляется очками новой системы.

## Соответствие механике

| Правило | Реализация |
|---|---|
| Конечный набор дел с избытком работы | Seed берётся из UUID новой смены; состав и расписание сохраняются в initial_state |
| Случайность | Категорийные квоты, перемешивание ситуаций и случайные занятые места; без повторов базовых сюжетов внутри одной смены |
| Один ход на задачу или завершённый этап | focus/overview и внутренние реплики не расходуют ход; конечный выбор и task расходуют ровно один |
| Нет ожидания | wait и ручной finish не предлагаются новым движком и отклоняются сервером |
| Не видны внутренние приоритеты/сроки | Публичная проекция не содержит категорий, расписания, seed, ttl или будущих событий |
| Осмотр | Конечный скрытый набор; обнаружение нескольких проблем; одно немедленное решение входит в ход осмотра. Повторный осмотр до завершения текущего запрещён |
| Автоисход | На границе хода истёкшие известные и скрытые проблемы получают авторский worst; причины видны в истории |
| Последний ход | Результат формируется сразу; известные, скрытые, запланированные дела и невыполненные задачи закрываются по своим последствиям |
| Критический таймер | Стартует при входе; 60/120 секунд; сервер проверяет срок перед командой, при reload/focus и по таймеру |
| Не более одной критической | Следующая критическая проблема ждёт освобождения активного слота |
| Фатальность | Только outcome.failShiftImmediately; Safety=0 и timeout сами по себе не заканчивают смену |
| Цепочки и обязательства | next/delay, tasks, task.requires, choice.requires, отложенный риск невыполненной приёмки, предотвращение повторной проблемы проверкой |
| Лояльность | Отдельно у каждого синтетического пассажира; HUD показывает арифметическое среднее |
| Безопасность | Общая шкала. Повышают только помеченные профилактические задачи; обычные проблемы не повышают безопасность |
| Компетенции | 0/1/2 за проблему; задачи — 0. SHIFT_SCORE=FACT/MAX×100 с округлением до сотых. Сумма завершённых смен хранится через уникальные записи результатов |
| Повторы запросов | requestId/revision, неизменяемый контент, транзакционная запись и точное воспроизведение сохранены |
| Итог | Сразу видны баллы, прирост, шкалы и количество завершённых/пропущенных дел. Решения, ошибки, задачи и журнал сгруппированы в раскрываемые разделы по уточнённому отзыву пользователя |

## Начальные параметры баланса

| Нагрузка | Ходы | Критические | Значимые | Обычные | Мелкие | Из них скрытые |
|---|---:|---:|---:|---:|---:|---:|
| Первое знакомство | 8 | 0 | 2 | 3 | 2 | 2 |
| Обслуживание и обязательства | 10 | 1 | 2 | 4 | 3 | 2 |
| Несколько дел одновременно | 16 | 2 | 4 | 5 | 4 | 3 |
| Полная смена | 20 | 2 | 5 | 6 | 6 | 4 |

Скрытые — часть квот, не дополнительное число. К набору добавляются две штатные обязанности и последствия выбранных решений. Всего в библиотеке 19 базовых ситуаций, 8 связанных стадий и 17 типов задач. 8 ступеней курса: две начальные смены Стандарт, затем по две смены Комфорт, Бизнес и Первый. Выбор следующей ступени и отметки прохождения сохраняются через серверную историю.

Порог уровня — 250 накопительных очков. Рейтинг суммирует результаты; недельный XP/СП старой версии в него не попадает. Прерванная вручную смена сохраняет полный разбор, но не даёт прироста компетенций; автоматический фатальный исход считается завершённой сменой и получает нормированный результат. Предотвращённая связанная проблема, которая не появилась, не входит в знаменатель. Предварительно сгенерированные проблемы входят в знаменатель и при досрочном окончании, чтобы пропуск не повышал оценку.

Это начальный настраиваемый баланс. Длительность 10–15 минут реальной игры не объявляется гарантированной: она зависит от чтения и обдумывания. Необходим дальнейший пользовательский плейтест.

## Интерфейс

Один компактный HUD с ходами, полосами лояльности/безопасности и отдельным реальным таймером при необходимости. Внизу: Дела, Вагон, Лог, Меню. Известные открытые проблемы и задачи показаны единым полным списком в «Делах». Внутренние экраны прокручиваются независимо; кнопки диалога имеют отдельную область, без промежуточных feedback-окон. После выбора видны его результат и последствия того же действия; полная история остаётся в логе.

Карта использует полную компоновку четырёх классов из согласованного референса `wagon-vsm.js`: Стандарт — 17 рядов / 85 мест, Комфорт — 18 рядов / 68 мест (четыре позиции занимает игровая комната), Бизнес — 17 рядов / 68 мест, Первый — 5 рядов / 15 мест в кресельном салоне плюс отдельные помещения. Это воспроизведение референса, не подтверждение финального заводского плана. Номера постоянные игровые: исходные слайды не содержат официальной билетной нумерации. Каждый номер виден всегда; метка обращения вынесена в угол и открывает реальную ситуацию. Высота кресла сохранена 38 px, карта не масштабируется по высоте; прокручивается игровая вкладка. Отдельные ранее созданные `wagon-*.html/js` сохраняются как экспериментальные страницы, не подключаются к игре.

## Проверки

Команды: `npm run check`, `npm test`, `npm run validate:scenarios`, `npm run validate:shift`, `npm run build:sites`. Дополнительно содержание Design002 проверяется при публикации и отдельным тестом.

Автоматические проверки охватывают разнообразие и квоты на 240 сочетаниях seed/нагрузки; ограничение критических событий на 70 сменах; атомарный осмотр; скрытые сроки; последний ход; развилки и условия задач; профилактику; фатальный и нефатальный таймауты; позднюю команду и повтор requestId; точное воспроизведение; накопление без подтверждения разбора; HTTP-прохождение всех четырёх классов; reload, рейтинг и администратора. Прежние тесты продолжают проверять сохранённый старый движок.

Для ручной браузерной проверки используется supervised preview и `qa/mobile.html` (390×844, 320×740), без данных рабочего сайта. Проверены приёмка, выбор известного обращения, осмотр со встроенным решением, маркеры карты, новые задачи, история и завершение. Отсутствие polling проверяется по счётчику API-запросов в неподвижной вкладке; возврат фокуса по-прежнему законно обновляет состояние.

## Публикация и восстановление

Порядок — [SITES-DEPLOYMENT.md](SITES-DEPLOYMENT.md). Публиковать в существующий `appgprj_6ab65220b22c8191bc605de177134df6`. Перед записью GitHub main сверить его SHA; использовать fast-forward, никогда force. В Sites перенести то же состояние исходников, собрать Worker, сохранить версию и развернуть. Новых D1-миграций нет: новый контент и состояния сохраняются в существующих таблицах. `publicationFingerprint` включает Design002, чтобы обновлённый контент публиковался один раз, а не при каждом действии.

Проверка `/api/health` должна показать `version: 4.0.0`, `engine: shift-4`. После выпуска проверить session/bootstrap/start/command/result. Откат UI/Worker к прежней версии не удаляет новую историю; для её открытия нужен движок shift-4. Не откатывать или очищать D1.

Финальная локальная проверка: 130 тестов прошли, `check`, `format:check`, обе проверки содержания и `build:sites` успешны. В браузере смена завершена на 8-м ходу: 71,43/100, +71,43 компетенций; после reload курс отметил 1/8 и предложил вторую смену. [Снимок мобильной главной](implementation/design002-mobile.jpg). Проверены размеры 390×844 и 320×740 без горизонтального переполнения; неподвижная вкладка не увеличивает счётчик API.

`dist/` удалён из отслеживаемых исходников и добавлен в ignore: он всегда получается сборкой, а не переносом старых бандлов. Ранее опубликованные экспериментальные страницы вагонов сохранены в исходниках и сборке.

## Дополнение: полный вагон, 27 сентября 2026

Единый `src/carriage-layouts.js` задаёт компоновку для карты и генератора пассажиров. Игровая комната исключается из набора кресел; номера уникальны. Новые смены закрепляют копию схемы в состоянии и контенте 1.0.2. Старые сохранения не перенумеровываются; места старого первого класса, отсутствующие в новой схеме, доступны отдельным блоком. Старый интерфейс shift-2/3 тоже показывает полный вагон и сохраняет переходы, статусы и проверку исполнения.

Проверки: уникальные номера всех четырёх схем, адреса событий на 48 сочетаниях класса/seed, переход по отмеченному креслу, сохранение старых адресов и неизменность формата старого начального состояния. В браузере: мобильные размеры 390×844 и 320×740, номер не закрывается меткой, кресло сохраняет высоту 38 px, прокрутка только внутреннего экрана, переход с кресла к диалогу.

## Дополнение: журнал и компактный итог, 27 сентября 2026

Контент 1.0.3 закрепляет `journalVersion: 2`: штатные задачи и записи создаются только после начала смены. До старта журнал и задачи пусты, в том числе при открытии старых сохранений. Во время смены журнал показывает только произошедшее: новые обращения без предварительного текста диалога, открытие обращения, выбранную реплику/решение, адрес и последствия. Скрытое появление и предотвращённые непоявившиеся проблемы доступны лишь в итоговом разборе. Полная история остаётся сохранённой. Изменения формата записи версионированы: точное воспроизведение старых смен не меняется.

В игре отдельная кнопка «Лог»; заголовок журнала — «Лог событий». Счётчик подписан «Ходы смены». Итог автоматически открывает короткую сводку и четыре закрытые группы подробностей: ошибки и пропуски, удачные решения, рабочие задачи, лог. На главной кнопки курса больше не наследуют ширину 100% внутри строки: название не сжимается до одного символа, на узком телефоне кнопка переносится под название.

Проверки: 137 тестов, check и build:sites. Добавлены регрессии на пустой журнал до начала, отсутствие предварительного диалога/скрытых событий, состав записей, компактный итог и exact replay новых записей. Отдельно проверено точное воспроизведение ранее сохранённой завершённой смены с контентом 1.0.0.

Браузерная приёмка этой доработки: новая смена пройдена от пустого журнала брифинга до автоматического итога на 8-м ходу (71,43/100, пять решённых обращений, три выполненные задачи). Проверены запись выбранного решения и адреса, раскрытие полного журнала, возвращение к курсу, размеры 390×844 и 320×740 без горизонтального переполнения. Проверка главной выполнена без активной смены, чтобы увидеть именно кнопки курса, вызывавшие исходную ошибку.

## Дополнение: реакции и сроки задач, 27 сентября 2026

Контент 1.2.0 закрепляет `taskLifetimeVersion: 1`. У задач теперь есть внутренний срок жизни: приёмка — первое завершённое рабочее действие, остальные задачи — 2–4 действия. Переходы, чтение и реплики без завершения этапа срок не расходуют. Новая задача после решения получает полное окно следующего действия. Просроченная задача закрывается один раз по своему worst; пропущенная приёмка создаёт отложенный дефект. Обычный осмотр остаётся доступным.

«Выполнить обслуживание» заменено подготовкой раздачи напитков: проверить запасы воды/чая и тележку. Выполнение открывает немедленное обслуживание заказа чая. Все известные открытые обращения и задачи идут общим списком без обрезания; во время осмотра остальные дела остаются видны, но недоступны до его завершения. Будущие и скрытые обращения не раскрываются.

Выбранная реакция показывается сразу в текущем экране вместе с изменением показателей и автоматическими последствиями. Осмотр, отказ от немедленного решения и срочный таймаут имеют собственные результаты. Подписи стоимости действия удалены также из старого интерфейса. Сроки задач игроку не показываются.

Проверки: `check`, **153/153** теста, `build:sites`, `git diff --check`. Независимый аудитор выполнил 100 новых смен / 1624 команды, повторный профильный запуск 20/20; сравнение старого и нового движка на закреплённом 1.1.0 — 25 смен / 565 команд с полным совпадением состояния. Найденные им ошибки реакции осмотра, таймаута и завершения осмотра исправлены и повторно проверены. Недетерминированное предположение journal-теста о гарантированном обращении на старте заменено реальным поиском через доступные действия.

В supervised preview проверен результат решения Wi-Fi, прирост личной лояльности, одновременное закрытие пропущенной приёмки, появление нового обращения и общий список. Размеры 390×844 и 320×740: горизонтального переполнения нет. [Мобильный результат](implementation/action-reaction-mobile.jpg).

Новые сроки действуют в новых сменах 1.2.0. Начатые ранее смены сохраняют закреплённые правила; обновление не пересчитывает их прошлое и не сбрасывает профили. Публикация использует тот же процесс и существующий Site из раздела выше; новых миграций нет.
